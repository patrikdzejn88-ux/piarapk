# План разработки piarapk (v2 переписка tg-piar)

Формат: фазы по очереди, каждая — параллельные агенты на подзадачи + параллельная
проверка результата. Данные от владельца подключаются по мере необходимости.

## Стек (зафиксировано исследованиями 27.09.2026)

- Flutter (Android APK — релиз; Windows — дев-скрипт) — UI, локальная БД (drift/sqlite)
  - таргеты: **Android + Windows** (мобильное приложение + десктоп для Windows)
- Rust-ядро: grammers (MTProto, автор Telethon) через flutter_rust_bridge 2.x
  - почему: TDLib не умеет импорт чужих сессий/tdata (проверено по официальным докам),
    pure-Dart MTProto-клиенты незрелые; grammers — layer 229, SRP-2FA,
    iter_participants, raw invoke (InviteToChannel, CreateChannel), AutoSleep flood
- dark.shopping — официальный API (dark.shopping/developer): каталог/заказы/баланс,
  ключ по заявке (баланс>0 + привязанный TG), оплата заказов только с баланса,
  автовыдача файлом; форматы: tdata, session, session+json, «вход по коду», 2FA
- CI: Codemagic облако (mac_mini_m2, бесплатных 500 мин/мес хватит; свой Mac mini
  Codemagic подключить не может — self-hosted runners не существуют)

## Ключевые решения

- Импорт tdata: парсим сами (порт TS-конвертера из tg-piar: AES-IGE/PBKDF2) →
  auth_key + dc_id → grammers SessionData → import_to (штатный механизм)
- Два пула аккаунтов раздельно: «пиар» и «парсер» (парсер жжёт акки — изоляция)
- Чат для инвайтов: broadcast-канал (участники по определению не могут писать)
  или supergroup с запретом прав — выбор в фазе 8
- Flood-политика: AutoSleep (порог 60с) + приложение-уровень: PEER_FLOOD →
  аккаунт в карантин, пауза, ротация
